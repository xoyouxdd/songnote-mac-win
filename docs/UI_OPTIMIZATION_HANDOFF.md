## Mac 定向验证步骤

在 Mac 取本轮源码后先执行下列命令，构建产物与测试可执行文件放仓库 `build/`。模型测试不要使用 `-O`，以保留断言。

```sh
mkdir -p build
swiftc -swift-version 5 macos/Models.swift tests/model.test.swift -o build/songnote-model-tests
build/songnote-model-tests
scripts/build-mac.sh
build/SongNote.app/Contents/MacOS/SongNote --check-layout
```

新增模型用例检查：旧 JSON 解码、草稿跨快照和重启保留、关窗移除、已有空便签不清理、续写副本来源、旧删除的三类后续意图、删除提示跨轮询和重启保留。原生布局检查使用七张内存便签，覆盖窄/默认/断点两侧/宽列表及正常、保存失败、冲突副本、删除拒绝四种最小/默认/大便签。

完成编译和几何检查后，用测试安装/测试服务器执行：

1. 截图核对标题栏系统按钮与四个图标、单行底部、六色、最窄冲突提示、默认列表至少六张卡片、宽窗奇数末行。标题栏工具必须能拖动周围空白区域，不能遮挡系统按钮。
2. 新建→什么都不写→关闭/退出，确认两端不出现空便签；颜色/列表置顶改变后属于有意保留的便签；写过再清空、旧空便签保留。模拟保存失败后取消退出，继续输入仍能保存。
3. 用拼音停留候选超过三秒，观察本机文件和另一端不出现候选字符串；候选中接收远端新编辑/删除，正式选字后的文字保留成副本。候选期间本机旧操作成功返回，不应制造无必要副本。关窗/退出时未确认的候选应取消，已保存文字仍保留；不要把 raw 拼音直接落盘。
4. 副本显示持久来源，原件能打开；原件删除时给说明。旧删除遭拒后即使轮询或重启仍有提示，确认后清除；副本自己遭拒删除同样提示。请求期间排队新删除不得自动删掉另一端新版。
5. 键盘在双列首/末行上下不横跳，筛选后选中和焦点有效；点击拖出不打开；右键对准的便签被管理；编辑时列表不跳顶，离开后重排；跨午夜时间更新。
6. 新窗口错位、恢复旧位置、断开外接屏、负坐标屏幕、已存在窗口再次打开。ID 迁移后保留本机窗口设置。
7. 开启/关闭系统减少动态设置，所有动效直接到最终状态；无编辑后台轮询不闪状态点。观察悬停、重排、新窗、换色、置顶、删除和失焦的实际流畅度。
8. 菜单栏置顶入口激活原窗口；开机启动默认关闭，点击后系统状态真实反映成功/待批准/失败。没有授权时不注册登录项。

## 尚需独立处理的既有同步风险

目前 Mac `Store.update` 会用新编辑替换同 ID 的单 `pending`；失败请求的冻结载荷没有独立持久队列。当服务端已接受但响应丢失，又继续编辑时，可能产生额外冲突副本，未达到 v1 对“失败后完全相同操作重试”的严格要求。本轮未重构整个重试队列；不能把现有模型的“请求期间续写”测试当作该网络边界已通过。

Windows 开工须按 [Windows README](../windows/README.md) 建立冻结在途操作与后续编辑分离的持久队列，并增加“服务端已接受但响应丢失+继续输入+重启”用例。Mac 后续如修复此项，需单独覆盖相同异常场景，再做双端联调；不需要扩展协议 v1。

后续更新：Windows 首版已按用户新授权实现，包含持久冻结队列；本机测试与 WPF 检查见 [Windows 验证记录](../windows/VALIDATION.md)。上表的 Windows“尚未开始”是本次 Mac 交接时的历史状态，当前以新验证记录为准。实际双端互通仍未验收，Mac 源码及其编译边界没有变化。发布和生产部署须另行授权。
