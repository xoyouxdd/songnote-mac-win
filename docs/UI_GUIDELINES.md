# SongNote 界面规范

更新：2026-10-03。「安静纸张」改版：列表改为中性底色的分组行，颜色只用小圆点标识；便签窗口保留纸面色但更柔和，首行显示为标题，标题栏和底部只保留必要信息。以原生桌面控件承载纯文本便签；列表便于找到内容，独立窗口尽量把空间留给书写。

## 颜色与尺寸

使用 sRGB，Mac 单位为 pt，Windows 为 DIP；坐标不跨设备同步。两端采用固定浅色纸面与深色文字，避免系统深色模式使六色混成灰色。系统高对比模式需另做可读性验证。

## 列表布局

标题栏左侧为「便签」，右侧只有一个「＋」图标（新建）。内容依次为搜索、分组列表、分隔线和底部状态。默认高度应能完整看到至少九行。

搜索框无描边、浅灰填充，左侧放大镜，占位文字「搜索」；输入后右侧出现清除按钮，Esc 清空，下方向键进入第一行。取消「全部 / 置顶」切换：固定在列表顶部的便签位于「已固定」分组，其余按修改日期分为「今天」「昨天」「更早」。空列表显示图标、「还没有便签」与快捷键提示，以及「新建便签」按钮。

滚动视口宽度小于 620 时单列；达到 620 时双列，每组内按行从左到右排列，分组标题占整行。上下方向键在双列时保持同一列，可跨分组移动。文档高度按分组与行数计算，任何宽度下行与分组标题不重叠、末行不被裁切。

每行包含颜色圆点、标题、右侧时间和一行预览；没有正文时预览显示淡色「没有更多内容」。时间在今天/昨天分组显示「HH:mm」，更早显示「M月d日」（跨年加年份）。冲突副本、删除未执行、待同步以短文字排在时间前，前两者用 warning 色；有附件时显示回形针和数量。状态更新复用按便签 ID 管理的行，避免同步时丢焦点。编辑窗口正处于正文输入时保留列表现有顺序和分组；离开编辑或关窗后按固定、修改时间重排。时间提示至少每 30 秒刷新，跨午夜从“今天”变为“昨天”。

## 独立便签

标题栏只保留图钉和更多两个图标，图标颜色取便签圆点色与 ink 的混合，与窗口按钮之间留出间隔。图钉表示「总在最前」：窗口浮在其他应用之上，只影响本机，不同步；采用空心/实心图钉及便签色调的浅色选中底，并提供可访问名称。「固定在列表顶部」（同步到两端的 pinned 字段）移入「更多」菜单和列表右键菜单。新建便签和返回列表也在「更多」菜单顶部，并保留 ⌘N / ⌘L（Windows 为 Ctrl+N / Ctrl+L）。Windows 便签窗口只有最小化和关闭：不提供最大化按钮，也屏蔽标题栏双击和 Win+↑ 的最大化；列表窗口保留完整三键，关闭键悬停为系统红 `#C42B1C`。

“更多”菜单右对齐弹在按钮下方（不跟随鼠标位置），最上方是新建便签和便签列表，其后是「固定在列表顶部」，再后是一排六色圆点，选中圆点有勾选和描边；每个圆点有颜色名称与辅助功能标签，另提供带色点和中文名称的原生子菜单供键盘使用。下方为“添加附件…”“总在最前（仅本机窗口）”和“删除便签…”。“固定在列表顶部”同步到两端，“总在最前”只修改当前设备的窗口层级。

删除仍需确认，确认文案说明 7 天内可恢复。删除后列表底部状态显示「已删除「标题」」和「撤销」按钮 8 秒；底部垃圾桶按钮（有可恢复便签时出现）、Mac 菜单栏和「便签」菜单、Windows 托盘都提供「最近删除」，列出 7 天内删除且有正文的便签，点击即恢复并打开。恢复是一次普通编辑，基于删除后的服务器版本提交；删除请求仍在发送途中就撤销时，按合并规则保留为冲突副本，不会丢内容。

冲突副本的提示条按钮为「对比」，打开对比窗口：左右并排显示原便签与冲突副本（各自纸面色、只读、可滚动），按钮为「打开原便签」「两份都保留」「保留原便签」「保留副本内容」。保留原便签会删除副本；保留副本内容会把副本正文和附件写回原便签（保留原 ID 与位置），再删除副本。被丢弃的一份进入「最近删除」。

任何应用中按 ⌥⌘N（Windows 为 Ctrl+Alt+N）直接新建一张便签；组合键被其他应用占用时静默跳过。

正文内边距横向 14、顶部 6，可调整窗口尺寸。Mac 首个非空行自动显示为标题，只改变显示属性，不写入任何格式。附件在正文下方显示为一排文件小标签（类型图标+文件名，最宽 150），放不下的收进「+N」；点标签弹出菜单下载或移除，点「+N」列出全部附件。底部平时只显示修改时间，立即同步图标隐藏；等待同步、草稿、离线、附件传输或下载进度时在时间后显示状态并出现同步图标；完整提示解释本机保存和服务器接收是两个阶段。保存失败时优先显示红色“本地保存失败，请勿退出”，同步暂停；立即同步先重试本地保存。离线或配置/响应异常显示文字和橙色，不能仅靠色点区分。另一台电脑仍需运行应用并联网，不把服务器接收描述为对端已显示。

冲突提示位于正文上方且不被下一次同步覆盖，样式为圆角提示条：图标+一行短文案+次要按钮，完整解释放在悬停提示里。副本为白色条「冲突副本 · 两份内容都已保留 / 原便签已删除」并可查看原件；删除遭拒为浅黄条「删除未执行：另一端有新内容」，用户点「知道了」后才清除；Windows 删除时本机保存失败为浅红条「保存失败，删除未生效」并提供「重试保存」。副本同时遭拒删除时，先显示删除提醒，确认后继续显示副本来源。列表底部提供查看提醒入口。

Windows 菜单统一为白底、圆角 8、浅阴影，悬停为暖灰 `#EFEEE8`，文字列对齐，删除项为红色；托盘菜单使用同一组暖色，不用 emoji 标记置顶便签。窗口使用系统阴影；Windows 11 由系统绘制圆角与 1px 边框，最大化时内容内缩，不被屏幕边缘裁切。

## 操作与保存

Windows 应用确认与错误提示共用纸面风格弹窗：暖白底、统一字体、圆角按钮，无系统问号图标。删除与移除附件使用明确的「删除 / 移除」按钮，默认聚焦「取消」；Esc、关闭与取消都不执行操作。错误提示用「知道了」关闭，长内容可滚动。文件打开与另存为仍使用系统原生选择框。

- Mac 快捷键：⌘N 新建、⌘L 列表、⌘F 搜索、⌘R 同步、⌘W 关窗、⌘Q 退出。Windows 统一用 Ctrl 对应业务快捷键，退出用托盘菜单。
- 卡片按下选中，鼠标松开且仍在卡片内才打开；拖出取消。方向键移动、Enter/Space 打开；双列上下按列移动，目标不存在时留在当前卡片。搜索框按下方向键进入第一张卡片。
- 卡片右键可直接固定在列表顶部、换色、删除；动作重新读取目标 ID 对应的当前内容，删除需确认。
- 新建空白便签先作为本机草稿保存，不提交服务器；第一次实际正文、颜色或固定状态改变后才入同步队列。未编辑空草稿关窗/退出时丢弃。已有空便签、编辑后清空的便签和另一端创建的空便签保留。
- 中文输入法候选文字不保存、不同步，也不被后台刷新覆盖；正式选字后保存。关窗/退出时取消尚未确认的候选，保留已提交文字。输入期间远端更新时保留输入开始的版本，提交后交由服务器保留冲突副本。仅接受本机已确认的成功回执来推进该基准，删除拒绝不能自动推进。
- 保留本机窗口位置、尺寸与打开状态。没有历史位置的新窗相对上个窗口向右下错开 24；恢复窗口前夹入当前显示器工作区，兼容负坐标及外接屏断开。
- 关闭列表后仍在菜单栏/托盘运行。菜单列出已固定的便签和最近删除，并提供开机启动；启动项勾选反映系统实际状态，失败或等待批准时明确说明。开机启动默认关闭，只有用户点击才更改。

## 动效

统一使用约 140–220ms 的轻量动效，不让每次后台轮询制造闪烁。尊重系统减少动态设置；开启时直接显示最终状态，并停止正在进行的动效。系统设置变化也应立即更新。

| 场景 | 动效 |
| --- | --- |
| 卡片悬停 | 纸面微亮、边框加深 |
| 增删和重排 | 卡片淡入/淡出，位置平滑移动；正在输入时不跳顶 |
| 同步 | 主动同步或提交编辑时图标旋转，完成状态点闪一次；无变化轮询保持安静 |
| 换颜色 | 纸面底色在 180ms 内过渡 |
| 打开新窗口 | 轻微放大淡入；已有窗口直接激活 |
| 总在最前 | 空心/实心切换并轻微弹性反馈 |
| 删除 | 140ms 淡出，余下卡片收起；退出中的卡片不再响应操作 |
| 便签不在前台 | 标题栏工具淡到 35%，重新激活恢复 |

## 状态文案

两端逐字一致，Mac 在 `macos/Texts.swift`，Windows 在 `SongNote.Core/Texts.cs`：

| 场景 | 文案 |
| --- | --- |
| 启动后尚未完成首次同步 | 正在连接… |
| 主动同步或提交编辑 | 正在同步… |
| 已同步 | 已同步 · HH:mm |
| 本机有未提交修改 | 等待同步 |
| 网络不可用 | 离线 · 内容已保存在本机 / 离线 · 等待同步 |
| 密钥错误 / 服务器错误 / 响应无效 | 同步密钥无效 / 同步失败（代码）· 稍后重试 / 同步响应无效 · 稍后重试 |
| 本机保存失败 | 本地保存失败，请勿退出 / 同步已暂停，等待本地保存 |
| 未编辑的空白便签 | 本机草稿 · 关闭空白窗口自动丢弃 |
| 冲突与删除被拒 | 检测到冲突 · 已保留两份内容 / 删除未执行 · 已保留另一端的新内容 |
| 附件上传失败 | 附件传输失败 · 文件已保留待重试 |
| Windows 未配置同步 | 尚未配置同步 · 内容只保存在本机 |

## 验证边界

2026-10-09 同步与交互优化：Mac 构建零警告，模型测试与 12 个共用合并用例通过，24 项原生检查覆盖撤销提示、对比窗口和空轮询不写盘；服务端 9 项测试通过（含增量同步）。Windows 改动只做了源码复查，未在 Windows 编译或运行：需执行核心测试（含共用用例与空轮询用例）和 `--ui-check`（已固定分组、总在最前、最近删除恢复、对比窗口），并实测 Ctrl+Alt+N。增量同步需要部署新版服务端后才生效；旧服务端下客户端自动退回完整快照。

2026-10-09 Windows 统一弹窗：本机构建零警告、零错误，62 项原生 WPF 检查通过；使用虚构内容验证确认、取消、Esc、关闭和错误提示，并核对渲染截图。文件选择仍走原生独立进程；本次未修改 Mac 或服务端。

同日修复 Windows 删除关窗崩溃：关窗失焦会同步刷新，在 Closed 移除窗口前重复 Close，触发 WPF 未处理异常。窗口在 OnClosing/OnClosed 标记生命周期，刷新跳过正在关闭或已关闭的窗口；取消关闭后恢复刷新。虚构便签完整新建、输入、确认删除的回归在修复前复现相同异常，修复后两次删除及取消关闭后再删除通过；28 项核心与 65 项原生 WPF 检查通过，构建零警告、零错误。

2026-10-03「安静纸张」改版：Mac 已在本机完成编译（零警告）、模型测试、20 项原生布局检查（分组列表、单/双列、首行标题样式、附件标签收拢）、签名校验，并用虚构便签截图核对列表与便签窗口；未安装到 /Applications，也未做真实输入法实测。Windows 改动只做了源码复查，未在 Windows 编译或运行，`--ui-check` 中的列表分组、九行默认高度和附件标签检查须在 Windows 上执行。Windows 暂不做首行标题样式（需将编辑框换成富文本控件并重新验证输入法），也未启用 Mica 背景。

Mac 源码在 Windows 上修改，语法解析与源码复核不替代 Swift/AppKit 编译。`--check-layout` 使用七张内存样例，检查单列/双列、奇数末行、标题栏、最窄便签、冲突提示和保存失败，不读取真实配置、不存文件、不连服务器。Mac 必须执行模型测试、构建、原生布局检查和真机输入/动画验证，清单见 [续作与验收](UI_OPTIMIZATION_HANDOFF.md)。Windows 已有 WPF 首版可执行程序并完成本机定向检查，详见 [Windows 验证记录](../windows/VALIDATION.md)；真实输入法、多屏和双端实机同步尚未验收。
