# Windows 端开工说明

更新：2026-10-03，版本 1.2.1。`src/SongNote.Windows` 为 WPF 客户端，`src/SongNote.Core` 为存储、同步和附件核心。Release 构建、28 项核心测试、49 项原生 WPF 检查和 2 项 Node 回环集成通过；真实输入法、多屏及 Mac 双端互通仍待验收，见 [验证记录](VALIDATION.md)。下文保留实现约束与验收要求。

从本目录运行 `python bootstrap-sdk.py` 准备项目内 SDK，再运行 `.\build.ps1 -Test -CheckUi -Integration`。可执行程序位于 `src/SongNote.Windows/bin/Release/net10.0-windows/SongNote.exe`；无同步配置时可离线使用，`--offline-demo` 将测试数据隔离在构建目录。

## 技术基线与模块

使用原生 WPF，支持 Windows 10/11。新项目以 `.NET 10 LTS` / `net10.0-windows` 为基线，使用当前受支持补丁；相比原文“.NET 8+”，避免在接近支持到期时启动新项目。依据：[微软支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy)。锁定 SDK 的 `global.json` 和构建说明随项目提交；运行时架构和安装方式在构建阶段按目标机器确认，不能照搬其它工业项目的 x86 默认值。

| 模块 | 责任 |
| --- | --- |
| Models / SyncContracts | 协议 JSON、Note/Change/Receipt、可向后兼容的本机状态 |
| LocalStore | 内容+pending+冻结在途操作+本机草稿+持久提醒一起原子保存，备份和错误处理 |
| SyncService / AttachmentFiles | 文字同步串行化，附件后台上传与按需下载，HTTPS、退避重试、内容校验和本机缓存 |
| MainViewModel / NoteViewModel | 搜索筛选、ID 选择、命令、状态文案；不直接操作 HTTP 或文件 |
| MainWindow / NoteWindow | 紧凑列表、独立编辑器、可访问工具栏和菜单；窗口按 ID 复用 |
| WindowPlacement / TrayService / StartupService | 只存本机的窗口坐标、窗口层级、托盘和开机启动 |
| Theme / MotionPolicy | 共享 Token、DPI/字体回退和系统减少动态策略 |

本机数据放 `%LOCALAPPDATA%\SongNote`，固定设备 ID 每台机器不同。图标用 `assets/SongNote.ico` 七尺寸；无登录页面，首次启动读取预置 `client-config.json`。无效配置或旧数据损坏时保留原文件并显示错误，禁止空数据覆盖。

## 分阶段实施

### 1. 本机可用与保存

先实现本机模型、存储、列表和单便签窗口：纯文本、搜索、6 色、列表置顶、删除确认、自动保存、撤销重做、单实例及窗口 ID 复用。新建空白草稿本机落盘但不入同步队列；首次实际编辑/颜色/列表置顶或添加附件后转成普通便签。未编辑草稿关窗丢弃，旧空便签或写过再清空的便签保留。

模型与队列用同一事务/原子文件；保存失败显示红色提示，停止网络提交。关闭/退出先提交已确认的输入；未落盘时允许重试或取消退出，取消后窗口仍有可保存的状态。不要用保存按钮代替自动保存。

### 2. 布局、配色与交互

采用 WindowChrome 提供窗口拖动和缩放，三个自绘系统操作按钮调用 SystemCommands，让标题栏跟随便签纸面颜色；原生布局已验证，最大化、不同 DPI 和真实多屏仍需人工验收。每张便签只有一行标题工具：新建、列表、列表置顶、更多；移除旧的两排按钮和总数。更多菜单提供附件、带勾选的六色圆点、名称选择、总在最前、删除。添加附件也可 Ctrl+O；使用应用内文件列表，多选或粘贴路径，文件夹读取在后台，不调用系统文件对话框。

列表默认 460×710，卡片高 84、间距 8，视口宽 620 切双列；最小内容 360×360。便签默认 380×420，最小内容 280×240。纸面、色条及文字直接采用 UI Token；预览 13、提示至少 11。底部一行状态+同步，保存失败短文案不得被截成无意义文字，完整错误可另展开。

实现 Ctrl+N/L/F/R、搜索下方向键进入列表、四方向卡片选择、Enter/Space 打开、鼠标松开打开与拖出取消、卡片右键管理。选中 ID 在重排/刷新后保留；正文输入时保持列表排序，离开编辑后重排。置顶采用明显图标和底色状态。

中文输入法使用 WPF 的文本组合事件识别候选阶段；不得把拼音候选写入持久状态或被同步响应覆盖。选字后保存，以组合开始时的服务器版本提交；本机已接受回执可以推进基准，远端新编辑/删除及拒绝删除不得自动推进。必须用真实微软拼音验证。

### 3. 双向同步

每 3 秒同步；编辑后延迟约 700ms；一次请求建议最多 4 条；错误退避 2–30 秒。请求在途仍可编辑，所有触发共享一个串行同步服务。标准 HTTPS 校验证书，不允许跳过证书或把同步密钥写进日志。

在请求发出前，原子保存其冻结 `op_id` 与完整载荷。失败/超时/重启后先重试完全相同的操作；后续编辑放新待提交队列，不能替换冻结操作。收到回执后只清理对应操作，按 v1 顺序更新后续编辑的版本与可能迁移的 ID，再叠加未提交正文。Mac 也已新增持久 frozen 队列，其原生运行边界仍需单独验证。

`conflict_copy` 保留两份内容，窗口及本机窗口设置迁移到回执 UUID，持久展示来源并允许查看原件；原件已删除要说明。`delete_conflict` 取消仍排队的删除意图，展示另一端新内容并持久提示；若请求期间继续编辑，保留该编辑的旧版本交由下次冲突处理，禁止自动按最新版重试删除。

本机草稿与删除提示是本地元数据，不新增协议字段。远端墓碑永久保留。未提交的离线编辑不得因读取快照被自动改版本。响应合并和队列原子落盘后再更新 UI；保存失败停止后续提交。

### 4. 托盘、启动和动效

关列表留在托盘，第一次明确提示“仍在托盘运行”；单便签关闭不等于删除，退出使用托盘菜单。托盘列出置顶便签，并提供开机启动开关；默认关闭，只在用户操作后注册，读取系统真实状态。恢复坐标前夹入某一当前显示器工作区，拔外接屏后仍可找到窗口。

统一实现悬停、重排/增删、同步旋转与完成提示、换色过渡、新窗轻微放大淡入、置顶反馈、删除淡出收起、失焦工具淡出。使用 UI 规范时长，并监听系统减少动态设置；关闭动画时直接到最终状态。无变化轮询不闪烁，输入时不跳顶，退出中的卡片不可操作。验证 CPU/内存和后台驻留，不持续开高频动画计时器。

## 配置与验收

配置模板为 `client-config.example.json`。真实配置只通过已授权的管理员 SSH/SFTP 从服务器私有目录取得；不通过公开链接下载，不提交 GitHub。实现与本机测试阶段不需要生产凭据；使用本地测试服务和虚构 Token。

| 必测流程 | 通过条件 |
| --- | --- |
| 保存失败与取消退出 | 内容还在编辑器且后续可重试保存，无空文件覆盖 |
| 空草稿/旧空便签 | 草稿跨快照保留、关窗丢弃、不在另一端出现；已有空便签保留 |
| 请求在途输入 | 回执不能覆盖新增文字，重启后队列继续提交 |
| 超时后服务已接受+续写 | 先重试原 op，再提交后续编辑，不重复复制或错误复用 op |
| 双端编辑与删除冲突 | 双份内容、正确 ID 迁移；拒绝删除不再次静默删除 |
| IME+远端编辑/删除 | 候选不保存、不被覆盖；正式选字内容保留成正确副本 |
| DPI/多屏/窄窗/双列奇数 | 所有系统按钮可用、卡片和状态不越界、方向键不乱跳 |
| 减少动态/后台轮询 | 立即停止动画，背景轮询保持安静 |
| 托盘/开机启动 | 用户能找到列表和退出，开关反映真实注册状态 |

交付顺序：模型/存储/同步定向测试 → WPF 构建 → 本机功能与截图验收 → 实际 Mac/Windows 双端互通。生产配置、部署与发布另需用户明确授权。共用协议变更须明确版本与兼容方案；2026-10-03 按用户授权同时改 Windows/Mac，附件使用 v1 可选字段与 health 能力协商，缺省字段保留旧客户端附件，详见同步协议。
